# 2회차 - 기본 명령어로 컨테이너 다뤄보기

## 🎯 학습 목표
- 컨테이너를 백그라운드로 실행하는 방법(`-d`) 이해하기
- 포트 매핑(`-p`)으로 컨테이너 서비스에 접속하는 원리 이해하기
- 컨테이너 실행(`run`) / 정지(`stop`) / 삭제(`rm`)의 차이 이해하기

---

## 📖 개념 정리

### 1. `-d` (detached) 옵션
`hello-world`는 실행 후 메시지만 출력하고 바로 종료(`Exited`)됐지만,
nginx 같은 웹서버는 **계속 떠 있어야** 요청을 받을 수 있다.

- `-d` 없이 실행 → 터미널이 컨테이너 로그에 붙잡혀서 다른 명령어를 칠 수 없음
- `-d`(detached, 백그라운드) 실행 → 컨테이너를 뒤에서 계속 띄워둔 채 터미널 제어권을 바로 돌려받음

### 2. `-p 호스트포트:컨테이너포트` (포트 매핑)
```
-p 8080:80
```
- 내 컴퓨터(호스트)의 **8080번 포트**로 들어오는 요청을 컨테이너 내부의 **80번 포트**(nginx 기본 포트)로 연결
- 컨테이너는 기본적으로 외부와 격리되어 있어서, 포트를 명시적으로 열어줘야 브라우저에서 접속 가능

### 3. `--name` 옵션
- 이름을 지정하지 않으면 Docker가 랜덤 이름(예: `vigorous_almeida`)을 자동으로 붙여줌
- `--name my-nginx`처럼 직접 이름을 지정하면 이후 명령어에서 컨테이너 ID 대신 이름으로 다루기 편함

### 4. `stop` vs `rm` (중요!)
| 명령어 | 의미 | 되돌릴 수 있나? |
|---|---|---|
| `docker stop` | 컨테이너를 **정지**만 함 | ✅ `docker start`로 재시작 가능 |
| `docker rm` | 컨테이너를 **완전 삭제** | ❌ 삭제되면 복구 불가 |

- `stop` 해도 `docker ps -a`에는 `Exited` 상태로 계속 남아있음
- 완전히 지우려면 `rm`까지 해줘야 함
- 컨테이너를 삭제해도 **이미지 자체는 그대로 남아있음** (컨테이너 삭제 ≠ 이미지 삭제)

### 5. `docker ps` vs `docker ps -a`
- `docker ps` → **실행 중인** 컨테이너만 표시
- `docker ps -a` → 정지된 것까지 **전체 이력** 표시

## 🧪 실습

### 1) nginx 컨테이너 실행
```bash
docker run -d -p 8080:80 --name my-nginx nginx
```
→ 컨테이너 ID(`7edda9f45b34...`)만 출력됨. `-d` 옵션 덕분에 로그 없이 바로 백그라운드 실행.

### 2) 실행 중인 컨테이너 확인
```bash
docker ps
```
```
CONTAINER ID   IMAGE     COMMAND                   CREATED          STATUS          PORTS                                     NAMES
7edda9f45b34   nginx     "/docker-entrypoint.…"   15 seconds ago   Up 14 seconds   0.0.0.0:8080->80/tcp, [::]:8080->80/tcp   my-nginx
```
- `STATUS: Up 14 seconds` → 실행 중
- `PORTS: 0.0.0.0:8080->80/tcp` → 8080(호스트) → 80(컨테이너) 매핑 확인

### 3) 브라우저 확인
`http://localhost:8080` 접속 → **"Welcome to nginx!" 페이지 확인 완료 ✅**

### 4) 정지
```bash
docker stop my-nginx
docker ps -a
```
- `STATUS`가 `Up` → `Exited (0)`으로 변경됨
- `PORTS` 컬럼이 비어있음 (더 이상 포트를 점유하지 않음 → 브라우저 새로고침 시 접속 안 됨)

### 5) 삭제
```bash
docker rm my-nginx
docker ps -a
```
- 목록에서 `my-nginx`가 완전히 사라짐 확인 완료 ✅

## ✅ 배운 점 / 정리
- `-d` 옵션으로 웹서버처럼 계속 떠 있어야 하는 컨테이너를 백그라운드로 실행할 수 있다는 걸 확인함
- `-p 8080:80` 포트 매핑 덕분에 브라우저로 컨테이너 안의 nginx에 접속할 수 있다는 걸 직접 확인함
- `stop`(정지, 되살릴 수 있음)과 `rm`(삭제, 되돌릴 수 없음)이 다른 개념이라는 걸 `docker ps -a` 결과 변화로 확인함
- 컨테이너를 지워도 이미지는 남아있다는 것 (컨테이너 ≠ 이미지)
